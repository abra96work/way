# Чек-лист тестирования «Путь»

Ручная проверка всех бизнес-процессов: от регистрации до чата и блокировок.
Подходит и для приложения, и для проверки API через Swagger (`/docs`) — в скобках
указан эндпоинт и ожидаемый код ошибки, если что-то пошло не так.

Отмечайте `[x]` пройденные пункты, в конце раздела — комментарии к найденным багам.

## 0. Подготовка

**Тестовые аккаунты** (код из СМС везде `111111`):

| Роль | Телефон | Для чего |
|---|---|---|
| Водитель А | +7 900 000-00-01 | основные поездки |
| Водитель Б | +7 900 000-00-02 | очередь машин, второй водитель |
| Пассажир В | +7 900 000-00-11 | основные брони, чат |
| Пассажир Г | +7 900 000-00-12 | конкуренция за места |
| Пассажир Д | +7 900 000-00-13 | **только для блокировки** — после теста заблокирован на 30 дней |
| Водитель Е | +7 900 000-00-03 | **только для блокировки** водителя |

**Важно перед стартом**

- Два физических устройства (или устройство + эмулятор/Swagger) нужны для чата, заявок
  и уведомлений: один человек — водитель, другой — пассажир.
- Лимит: водитель публикует **1 поездку в сутки + 1 обратную**, не больше **10 за календарную неделю** (пн–вс), не дальше **3 дней**
  вперёд. Планируйте поездки на разные дни или используйте разных водителей.
- «Сутки» считаются по времени Екатеринбурга (UTC+5).
- Поездка становится «завершённой» через **6 часов после отправления** — сценарии
  завершённых поездок проверяются на следующий день или на тестовом стенде.
- Блокировка снимается только через 30 дней (админки пока нет) — для неё отдельные аккаунты.
- Все ошибки приходят как `{"code": "...", "message": "..."}`; `message` — по-русски,
  его и должно показывать приложение.

## 1. Онбординг, регистрация, вход

- [ ] **1.1** Первый запуск: показывается онбординг «для кого приложение и как пользоваться», после него — вход в приложение.
- [ ] **1.2** Выбор города из списка доступных; поиск по названию работает без учёта регистра и «е/ё» (`березов` → Берёзовский) (`GET /cities?query=`).
- [ ] **1.3** Ввод телефона в разных форматах: `+7 (900) 000-00-01`, `89000000001`, `9000000001` — все принимаются как один номер.
- [ ] **1.4** Некорректный телефон (`123`, буквы) — понятная ошибка, код не запрашивается (`validation_error`).
- [ ] **1.5** Запрос кода → ввод `111111` → вход. Новый пользователь попадает на заполнение профиля (`is_new_user: true`).
- [ ] **1.6** Неверный код → «Неверный код» (`invalid_code`); после 5 неверных попыток → «Слишком много попыток» (`too_many_attempts`), помогает только новый запрос кода.
- [ ] **1.7** Повторное использование уже введённого кода не работает (`code_expired`).
- [ ] **1.8** Заполнение профиля: имя (обязательно), фото-аватар. Пустое имя/пробелы не сохраняются (`first_name_required`).
- [ ] **1.9** Выбор роли: «Водитель» или «Пассажир» → переход в соответствующий раздел; один аккаунт может пользоваться обоими разделами.
- [ ] **1.10** Повторный вход тем же номером → тот же аккаунт и данные (`is_new_user: false`).
- [ ] **1.11** Приложение не разлогинивает через 15 минут: токен обновляется автоматически (`POST /auth/refresh`).
- [ ] **1.12** Выход из аккаунта → нужно войти заново; старая сессия не работает (`POST /auth/logout`, затем `invalid_refresh_token`).

## 2. Профиль

- [ ] **2.1** Профиль показывает имя, фамилию, фото, город; всё редактируется (`GET/PATCH /me`).
- [ ] **2.2** Аватар: JPEG/PNG/WebP загружаются и отображаются; замена фото заменяет картинку.
- [ ] **2.3** Не-картинка (PDF, txt, переименованный файл) → ошибка `unsupported_file_type`; файл > 5 МБ → `file_too_large`.
- [ ] **2.4** Фото лица водителя (анфас) загружается, статус «на проверке» (`PUT /me/face-photo`, `face_photo_status: pending`).
- [ ] **2.5** Рейтинг нового пользователя: **5 звёзд, «нет отзывов»** (`rating: 5.0`, `reviews_count: 0`).
- [ ] **2.6** Раздел «Жалобы» пустой у нового пользователя (`GET /me/complaints`).
- [ ] **2.7** Чужой профиль (водителя из поездки) показывает имя, фото, рейтинг — **без телефона** (`GET /users/{id}`).

## 3. Водитель: мои автомобили

- [ ] **3.1** Добавление ТС: марка из списка → модели этой марки → вместимость → фото → тип «Легковой/Автобус» (`GET /cars/brands`, `/models`, `POST /cars`).
- [ ] **3.2** Поиск марки по названию (`газ` → ГАЗ).
- [ ] **3.3** Лимит мест: легковой — не больше 8, автобус — не больше 60 (`too_many_seats`).
- [ ] **3.4** Госномер необязателен; `а 777 аа 66` сохраняется как `А777АА66`; буквы не из госномеров (`Ж`) не принимаются.
- [ ] **3.5** Фото автомобиля загружается и видно в карточке (`PUT /cars/{id}/photo`).
- [ ] **3.6** Редактирование ТС (модель, места, номер) сохраняется.
- [ ] **3.7** Удаление ТС убирает его из списка.
- [ ] **3.8** ТС, стоящее в активной поездке, удалить нельзя (`car_used_by_trips`); уменьшить места ниже указанных в поездке нельзя (`car_seats_used_by_trips`).
- [ ] **3.9** Другой пользователь не видит и не может изменить чужое ТС (404).

## 4. Водитель: создание поездки

- [ ] **4.1** Шаг «Маршрут»: пункт отправления, остановки, пункт прибытия (город + адрес). Отправление и прибытие в одном городе — нельзя.
- [ ] **4.2** Шаг «Дата и время»: время только кратно 30 минутам (`10:00`, `10:30`); `10:15` не принимается.
- [ ] **4.3** Количество пассажиров не больше мест выбранного ТС (`seats_exceed_car`).
- [ ] **4.4** Шаг «Цены»: цена всего маршрута, цены между соседними остановками, минимальная цена «за посадку». Без цены между какими-то соседними остановками — ошибка; минимальная больше полной — ошибка.
- [ ] **4.5** Пассажирская цена = цена водителя + 10 %: водитель ставит 1000 → пассажир видит **1100** (`driver_price`, `commission`, `passenger_price`).
- [ ] **4.6** Выбор ТС из «Мои автомобили»; чужое/удалённое ТС не принимается (`car_not_found`).
- [ ] **4.7** Доп. услуги с ценой: детское кресло, животные, багаж; посылки S/M/L с ценой и габаритами (`GET /trips/parcel-sizes`).
- [ ] **4.8** Режим бронирования: «Стандартный» (подтверждение водителем) и «Быстрый» (сразу оплата).
- [ ] **4.9** «Сохранить» без публикации → черновик; черновик виден только водителю.
- [ ] **4.10** Публикация черновика (`POST /trips/{id}/publish`); повторная публикация → `trip_not_draft`.
- [ ] **4.11** Публикация без имени в профиле → `profile_incomplete`.
- [ ] **4.12** Время в прошлом → `departure_in_past`; дальше 3 дней → `departure_too_far` (в приложении календарь показывает сегодня + 3 дня) (черновик на дальнюю дату сохранить можно).
- [ ] **4.13** Лимит: вторая поездка в тот же день в том же направлении → `daily_trip_limit`; поездка **в обратном направлении** в тот же день — можно; третья — нельзя.
- [ ] **4.13a** В приложении при лимите открывается диалог «Достигнут лимит» со счётчиками «Туда / Обратно», кнопка «Сохранить как шаблон» сохраняет черновик.
- [ ] **4.13b** После публикации экран «Заказ опубликован!» показывает «Сегодня N / 2» и «На неделе N / 10» (`GET /trips/limits`); 11-я поездка за неделю → `weekly_trip_limit`.
- [ ] **4.13c** «Создать обратную поездку» → маршрут в обратном порядке, цены, авто и доп. услуги те же; нужно выбрать только дату и время → шторка «Опубликовать поездку?» → публикуется.
- [ ] **4.14** «Обратная поездка»: маршрут и цены разворачиваются, нужно указать только время старта (`POST /trips/{id}/reverse`).
- [ ] **4.15** Время отправления отображается одинаково у водителя и пассажира (часовой пояс не «съезжает»).

## 5. Водитель: мои поездки

- [ ] **5.1** Вкладки: активные / завершённые / черновики / отменённые (`GET /trips/mine?status=`).
- [ ] **5.2** Карточка: откуда, куда, дата/время, статус, свободные места.
- [ ] **5.3** Редактирование поездки, пока никто не присоединился (`PUT /trips/{id}`).
- [ ] **5.4** После первой заявки пассажира редактировать маршрут/время/цены нельзя (`trip_has_bookings`), `is_editable: false`.
- [ ] **5.5** Количество свободных мест можно менять и после броней; ниже занятых — нельзя (`seats_below_booked`).
- [ ] **5.6** Удалить поездку без пассажиров — можно; с пассажирами — только отменить (`trip_has_bookings`).
- [ ] **5.7** Список заявок/пассажиров поездки с профилем и рейтингом пассажира (`GET /trips/{id}/bookings`).

## 6. Пассажир: поиск поездки

- [ ] **6.1** Список поездок; вкладки «Автомобили» / «Автобусы».
- [ ] **6.2** Фильтр по пунктам начала и конца маршрута (по городу и по названию).
- [ ] **6.3** **Промежуточные остановки**: поездка А → Б → В находится по запросу «Б → В», цена в карточке — за отрезок Б → В.
- [ ] **6.4** Поездка в обратную сторону не находится (запрос «В → А» для поездки А → В).
- [ ] **6.5** «Поблизости»: поделиться геолокацией → поездки с посадкой в радиусе, расстояние в карточке.
- [ ] **6.6** Фильтр по дате и по числу мест.
- [ ] **6.7** В поиске нет: своих поездок, черновиков, отменённых, уже отправившихся.
- [ ] **6.8** Ранжирование: выше водители с большим числом поездок и меньшим числом отмен, затем — ближайшее время.
- [ ] **6.9** Карточка: откуда, куда, дата/время, тип ТС, цена, свободные места, водитель с рейтингом («5 звёзд, нет отзывов» у нового).
- [ ] **6.10** Детали поездки: остановки, места, общая цена и цены между остановками, минимальная цена, авто (марка/модель/фото), доп. услуги, посылки, водитель (имя, фото, рейтинг).

## 7. Очередь машин на одном маршруте

Водители А и Б публикуют поездки по одному маршруту на одно и то же время.

- [ ] **7.1** В поиске видны обе; «идёт регистрация» (`is_registration_open: true`) — только у первой (выше приоритет водителя, при равенстве — раньше опубликована).
- [ ] **7.2** Бронирование второй машины, пока первая не заполнена → «Регистрация откроется после заполнения предыдущей» (`registration_closed`).
- [ ] **7.3** После заполнения всех мест первой машины открывается вторая.

## 8. Бронирование и оплата

**Стандартный режим** (поездка водителя А, пассажир В):

- [ ] **8.1** Перед бронью виден расчёт: цена места на отрезке, доп. услуги, итог, комиссия (`POST /bookings/quote`).
- [ ] **8.2** Бронь места → статус «ждёт подтверждения» (`pending`); у водителя появляется заявка и уведомление.
- [ ] **8.3** Водитель открывает профиль пассажира из заявки: имя, фото, рейтинг.
- [ ] **8.4** Водитель отклоняет → у пассажира «отклонена», места освобождаются, уведомление пассажиру.
- [ ] **8.5** Водитель подтверждает → у пассажира запрос на оплату с **суммой комиссии**; уведомление.
- [ ] **8.6** Оплатить до подтверждения нельзя (`booking_not_payable`).
- [ ] **8.7** «Оплатить» → сразу «Оплачено» (заглушка); видно: общая сумма, комиссия (оплачена), сумма к оплате водителю; водителю уведомление.
- [ ] **8.8** Повторная оплата невозможна.

**Быстрый режим:**

- [ ] **8.9** Бронь сразу переходит к оплате (`awaiting_payment`), без подтверждения водителя; водителю уведомление о брони.

**Ограничения:**

- [ ] **8.10** Нельзя забронировать свою поездку (`own_trip`).
- [ ] **8.11** Нельзя без имени в профиле (`profile_incomplete`).
- [ ] **8.12** Вторая активная бронь места в той же поездке → `already_booked` (посылка — отдельно, можно).
- [ ] **8.13** Доп. услуга, которую водитель не предлагает → `extra_not_offered`.
- [ ] **8.14** Мест больше, чем свободно на отрезке → `not_enough_seats`.
- [ ] **8.15** Бронь отменённой/отправившейся поездки невозможна (`trip_cancelled` / `trip_departed`).
- [ ] **8.16** Водитель не может оплатить за пассажира, пассажир не может подтвердить свою заявку.

**Мои поездки пассажира:**

- [ ] **8.17** Вкладки: активные / завершённые / отменённые (`GET /bookings/mine?status=`); в деталях — маршрут, места, доп. услуги, авто, водитель, цена.

## 9. Места по отрезкам

Поездка А → Б → В на 3 места.

- [ ] **9.1** Пассажир В бронирует 3 места А → Б.
- [ ] **9.2** Пассажир Г может забронировать 3 места Б → В (места освободились в Б).
- [ ] **9.3** Бронь А → В невозможна (`not_enough_seats`); в поиске «А → В» поездки нет, «Б → В» — тоже нет (заполнено), до брони Г — была.
- [ ] **9.4** Свободные места в деталях поездки и в «Мои поездки» водителя пересчитываются.

## 10. Посылки

- [ ] **10.1** Отправка посылки без поездки пассажира: выбор размера S/M/L, видны максимальные габариты и вес.
- [ ] **10.2** Цена посылки = цена водителя + 10 %; посылка не занимает пассажирские места.
- [ ] **10.3** Размер, который водитель не принимает → `parcel_not_accepted`; у водителя без цен на посылки — посылки недоступны (`accepts_parcels: false`).
- [ ] **10.4** Подтверждение/оплата посылки проходят так же, как бронь места.

## 11. Отмены и блокировка (правила сообщества)

**Без нарушения:**

- [ ] **11.1** Пассажир отменяет заявку, которую водитель ещё не подтвердил → без предупреждения (`sanction.is_violation: false`), места освобождаются.
- [ ] **11.2** Водитель отменяет поездку без зарегистрированных пассажиров → без предупреждения.

**Пассажир (аккаунт Д):**

- [ ] **11.3** Перед отменой подтверждённой/оплаченной брони показывается предупреждение «о нарушении правил сообщества» (`GET /bookings/{id}/cancel-preview`).
- [ ] **11.4** Первая такая отмена → предупреждение, аккаунт не заблокирован; водителю уведомление об отмене.
- [ ] **11.5** Перед второй отменой за 30 дней видно, что она **заблокирует аккаунт** (`blocks_account: true`).
- [ ] **11.6** Вторая отмена → блокировка на 30 дней: уведомление, в профиле дата окончания блокировки.
- [ ] **11.7** Заблокированный пассажир не может бронировать (`user_blocked`) и писать в чат.
- [ ] **11.8** В быстром режиме отмена сразу после брони — тоже нарушение.

**Водитель (аккаунт Е):**

- [ ] **11.9** Отмена поездки с подтверждёнными/оплаченными пассажирами → предупреждение; все брони отменяются, пассажирам уведомление «Водитель отменил поездку».
- [ ] **11.10** Вторая такая отмена за 30 дней → блокировка; заблокированный водитель не может публиковать поездки (`user_blocked`).
- [ ] **11.11** Отмена уже отправившейся поездки/брони невозможна (`trip_departed`, `trip_not_active`).

## 12. Чат водителя и пассажира

Два устройства: водитель А и пассажир В с бронью в поездке А.

- [ ] **12.1** Пассажир открывает чат из своей брони, водитель — из заявки/списка пассажиров; это **один и тот же** чат.
- [ ] **12.2** Сообщение пассажира **сразу** появляется у водителя без обновления экрана (WebSocket); и наоборот.
- [ ] **12.3** Свои сообщения справа/помечены «мои», чужие — слева.
- [ ] **12.4** Список чатов: последнее сообщение, счётчик непрочитанных, собеседник, поездка; общий счётчик на иконке «Чаты».
- [ ] **12.5** Открыл чат → непрочитанные обнулились; у собеседника появилась отметка «прочитано».
- [ ] **12.6** Длинная переписка: при прокрутке вверх подгружаются старые сообщения.
- [ ] **12.7** Пустое сообщение / только пробелы не отправляется.
- [ ] **12.8** После отмены брони или завершения поездки писать нельзя (`chat_closed`), история читается.
- [ ] **12.9** Посторонний пользователь не может открыть чужой чат (404).
- [ ] **12.10** Потеря сети / сворачивание приложения: после возвращения пропущенные сообщения подгружаются, сокет переподключается.

## 13. Уведомления

- [ ] **13.1** Водителю: новая заявка, новая бронь (быстрый режим), оплата, отмена брони пассажиром.
- [ ] **13.2** Пассажиру: подтверждение (с суммой к оплате), отклонение, отмена поездки водителем.
- [ ] **13.3** Пользователю: блокировка аккаунта.
- [ ] **13.4** Счётчик непрочитанных, «прочитать», «прочитать все»; из уведомления можно перейти к поездке/брони.

## 14. Рейтинг, отзывы, жалобы

- [ ] **14.1** У всех без отзывов — «5 звёзд, нет отзывов» в поиске, деталях поездки и профиле.
- [ ] **14.2** Оставить отзыв в приложении нельзя (по ТЗ); API отвечает `reviews_disabled`.
- [ ] **14.3** После завершённой поездки (через 6 ч после отправления) растёт число поездок у водителя и пассажира.
- [ ] **14.4** Отмены-нарушения понижают позицию водителя в поиске.
