# «Путь»: единые требования и чек-лист тестирования

Версия документа: 24 ноября 2026 года  
Назначение: единый контекст для отдельного чата/исполнителя, который будет проверять мобильное приложение, API и соответствие продукта требованиям.

- Текстовые требования и стикеры в Figma имеют приоритет над визуальным макетом, если между ними есть противоречие.
- Этот документ объединяет переданные владельцем проекта требования. Если поведение отсутствует и здесь, и в API/макете, его нельзя придумывать: нужно зафиксировать вопрос.
- Чёрные стрелки, линии, рамки выделения и подписи вокруг мобильных фреймов в макете не являются частью интерфейса.

## 2. Контекст продукта

«Путь» — аналог BlaBlaCar для малых городов и населённых пунктов России. Приложение заменяет офлайн-поиск маршрутки или водителя и личные договорённости цифровым процессом:

- пассажир находит поездку, бронирует место или отправку посылки;
- водитель публикует маршрут, управляет местами и подтверждает пассажиров;
- обе роли могут общаться в чате по незавершённой поездке.

Клиент разрабатывается на Flutter. Основной API имеет префикс `/api/v1`.

## 3. Общие продуктовые правила

### 3.1. Тестовые ограничения

- Реальная отправка SMS не подключена. Валидный код подтверждения на всех экранах: `111111`.
- Реальный эквайринг не подключён. Нажатие «Оплатить» должно сразу переводить сущность в состояние «Оплачено».
- Приложение ориентировано на РФ. Проверка на устройстве физически за пределами РФ допустима, но продукт и тексты должны быть рассчитаны на российский рынок.
- Хостинг не является обязательной частью тестового задания.

### 3.2. Рейтинг и отзывы

- Интерфейс создания отзывов не входит в объём тестового задания.
- Если отзывов нет, в UI показывается: «5 звёзд, нет отзывов»; числовой рейтинг — `5,0`.
- Модель данных может сохранять задел под полноценные отзывы.
- Рейтинг зависит от количества завершённых поездок и отмен: больше поездок и меньше отмен должны давать более высокий рейтинг. Точная формула в требованиях не задана и не должна выдумываться на клиенте.

### 3.3. Деньги

- Водитель задаёт базовую цену поездки.
- Сверху добавляется комиссия 10 %. Пример: `1 000 ₽ + 100 ₽ = 1 100 ₽`.
- Денежные значения отображаются целыми рублями, с неразрывными пробелами в тысячах: `1 250 ₽`.
- При включённой монетизации пассажир:
  1. в списке поездок видит общую стоимость поездки;
  2. после запроса на оплату видит сумму комиссии, которую нужно оплатить;
  3. после оплаты видит общую сумму, комиссию и сумму к передаче водителю.
- Стоимость между остановками задаётся для конкретных пар точек маршрута, а не как единая цена за километр. Допустима нелинейная цена: на коротком участке стоимость одного километра может быть выше.
- Минимальная цена «за посадку» применяется независимо от рассчитанной стоимости между остановками.

### 3.4. Время, изображения и ошибки API

- Время приходит из API в UTC и перед отображением переводится в локальный часовой пояс устройства.
- Относительные пути изображений вида `/media/...` дополняются базовым адресом API.
- Ошибки API имеют вид `{code, message, details}`. Пользователю показывается русскоязычное поле `message`, а не технический код или stack trace.
- Сетевые операции должны иметь состояния загрузки, отсутствия интернета и общей ошибки с возможностью повторить запрос.

### 3.5. Базовые визуальные токены

- основной зелёный: `#1EB74D`;
- основной текст: `#0C0C0C`;
- фон: `#F1F2F3`;
- разделитель: `#E4E5E6`;
- вторичный текст: `0x7F0C0C0C`;
- используется системный шрифт; Gilroy не подключается.

## 4. Сквозные пользовательские сценарии

### 4.1. Онбординг

- Приложение пошагово объясняет, для кого оно создано и как им пользоваться.
- После прохождения онбординга пользователь переходит к началу работы с приложением.
- Повторный запуск не должен бесконечно возвращать уже прошедшего онбординг пользователя на первый слайд.

### 4.2. Выбор города или населённого пункта

- До начала работы пользователь выбирает город/населённый пункт из доступного списка.
- Поиск фильтрует список по введённому названию.
- Выбранный город используется как начальный контекст поиска и создания заказа.

### 4.3. Авторизация и регистрация

- Регистрация выполняется по номеру телефона.
- После ввода номера открывается ввод SMS-кода; тестовый код — `111111`.
- После подтверждения номера пользователь заполняет имя и добавляет фотографию/аватар.
- После регистрации пользователь выбирает роль или режим: «Водитель» либо «Пассажир».
- Роль можно позднее переключить из профиля без создания второго аккаунта.
- Выход использует существующий серверный logout, очищает авторизацию и возвращает на экран входа.

## 5. Пассажир

### 5.1. Поиск поездки

- Отображается список доступных поездок на легковых автомобилях и автобусах.
- Приоритет карточек зависит от:
  - рейтинга и количества поездок водителя: более опытный водитель с более высоким рейтингом находится выше;
  - близости времени отправления к текущему моменту.
- Если существуют две одинаковые поездки по направлению и времени:
  - в списке показываются обе;
  - только одна доступна для текущей регистрации пассажиров;
  - активная карточка имеет зелёный статус «Идёт регистрация»;
  - когда места в первой закончатся, регистрация открывается для следующей.
- Краткая карточка содержит как минимум:
  - пункт отправления;
  - пункт прибытия;
  - дату и время отправления;
  - тип транспорта: легковой автомобиль или автобус;
  - цену;
  - данные водителя и доступные статусы поездки.

### 5.2. Фильтры и геолокация

- Приложение запрашивает разрешение на геолокацию и получает координаты устройства.
- При отказе или недоступности геолокации остаётся поиск по названию города.
- Поиск «поблизости» использует координаты и радиус.
- Сейчас координаты остановок могут отсутствовать: тогда используется центр города. Для крупных городов это снижает точность и должно учитываться при тестировании как известное ограничение, а не как точная геопозиция остановки.
- Если при создании поездки переданы `lat`/`lng` конкретной остановки, поиск должен использовать их.
- Активный фильтр визуально отмечается; очистка возвращает полный список.

### 5.3. Детали поездки

По нажатию на карточку открывается подробная информация:

- весь маршрут и остановки, на которых можно присоединиться;
- пункт посадки и пункт высадки;
- дата и время;
- доступное количество пассажирских мест;
- доступность/параметры посылки;
- стоимость всей поездки и стоимость между остановками;
- минимальная стоимость посадки;
- дополнительные услуги: детское кресло, животные, багаж, посылка;
- автомобиль: марка, модель и фотография;
- водитель: имя, фото профиля, рейтинг и количество поездок;
- кнопки бронирования, отправки посылки и связи с водителем — в зависимости от состояния поездки.

### 5.4. Бронирование места

- Пассажир выбирает точки посадки и высадки.
- Пассажир выбирает количество мест.
- Нельзя забронировать больше мест, чем доступно в автомобиле.
- Дополнительные услуги выбираются явно: детское кресло, багаж, животные.
- Стандартное бронирование:
  1. водитель получает заявку;
  2. водитель открывает профиль пассажира и подтверждает либо отклоняет заявку;
  3. после подтверждения пассажир получает предложение оплатить;
  4. тестовая оплата сразу меняет статус на «Оплачено».
- Быстрое бронирование:
  - отдельное подтверждение водителя не требуется;
  - пассажир сразу переходит к оплате.
- Отклонение водителем отображается пассажиру понятным сообщением и не создаёт оплаченной брони.

### 5.5. Отправка посылки

- Посылку можно добавить к поездке как дополнительную услугу.
- Доступны размеры `S`, `M`, `L`; для каждого должны быть заданы предельные габариты/вес и цена.
- Возможна отправка посылки без пассажирского места.
- Итоговая стоимость должна учитывать выбранный размер посылки и комиссию согласно правилам продукта.

### 5.6. «Мои поездки» пассажира

- Отображается список бронирований/поездок, к которым присоединился пассажир.
- Поддерживаются состояния/фильтры как минимум: активные, завершённые, отменённые; общий список не должен терять карточки.
- Пустое состояние содержит предусмотренную дизайном иллюстрацию и действие для создания/поиска заказа.
- В карточке и деталях доступны:
  - пункты отправления и прибытия;
  - дата и время;
  - запланированные остановки;
  - количество пассажирских мест;
  - количество/размер мест для посылок;
  - стоимость поездки и отправки посылки;
  - дополнительные услуги;
  - марка, модель и фото автомобиля;
  - имя, фото и рейтинг водителя.
- Написать водителю можно только по незавершённой поездке.

### 5.7. Отмена бронирования и возврат

- Перед отменой выполняется предварительный запрос условий отмены и показывается предупреждение.
- Для обычной отмены показываются:
  - сумма возврата;
  - срок возврата;
  - счётчик отмен за последние 30 дней.
- После подтверждения отмены показывается успешный экран и сумма возврата; деньги возвращаются на ту же карту в указанный срок.
- Если это повторная отмена за 30 дней, пользователь должен увидеть отдельное предупреждение о блокировке.
- Две отмены в течение 30 дней автоматически блокируют пассажира на 30 дней.
- После блокировки показан отдельный экран «Аккаунт временно заблокирован», срок/причина и понятное дальнейшее действие.
- Информация о блокировке доступна администратору в базе данных.

## 6. Водитель

### 6.1. Создание поездки

Водитель может создать поездку и указать:

- пункт отправления;
- пункт прибытия;
- плановые остановки;
- дату и время отправления; время выбирается с шагом 30 минут;
- количество пассажирских мест;
- цену от начала до конца маршрута;
- цены между остановками;
- минимальную цену посадки;
- автомобиль из списка машин, привязанных к аккаунту;
- платные дополнительные услуги: детское кресло, животные, багаж, посылки `S`/`M`/`L`;
- стандартное или быстрое бронирование.

Водитель также может:

- сохранить поездку;
- редактировать её, пока не присоединился ни один пассажир;
- создать обратную поездку с теми же данными и маршрутом в обратном порядке, отдельно задав время начала;
- дублировать поездку в пределах продуктовых ограничений.

Ограничения публикации:

- не более одной поездки в сутки в прямом направлении;
- дополнительно не более одной поездки в сутки в обратном направлении;
- публиковать поездки можно не более чем на 3 дня вперёд.

### 6.2. «Мои поездки» водителя

- Отображается список опубликованных поездок.
- Карточка содержит отправление, прибытие, дату/время и актуальный статус: активная или завершённая.
- Водитель видит заявки пассажиров и может открыть профиль каждого:
  - имя и фамилия;
  - фотография;
  - рейтинг.
- Водитель может написать пассажиру в чат.
- Водитель может изменять количество свободных мест.
- Редактирование и удаление поездки доступны только до присоединения первого пассажира.
- Если водитель отменяет поездку после регистрации хотя бы одного пассажира, показывается предупреждение о нарушении.
- Две такие отмены за 30 дней блокируют водителя на 30 дней.
- Информация о блокировке доступна администратору в базе данных.

## 7. Профиль и роли

- Профиль показывает данные, указанные при регистрации, и разрешает редактировать имя/фамилию и фото.
- Для водителя обязательна фотография лица анфас; она проходит проверку администратором.
- Показываются рейтинг и количество поездок.
- Доступен список жалоб, полученных пользователем.
- Доступно переключение между режимами пассажира и водителя.
- Доступен выход из аккаунта с подтверждением.
- Нельзя создавать независимые профили для двух ролей: режимы относятся к одному аккаунту.

## 8. Чат и уведомления

- Чат доступен между участниками конкретной поездки.
- Пассажир может написать водителю только для незавершённой поездки.
- Водитель может написать пассажиру, подавшему заявку/присоединившемуся к поездке.
- Непрочитанные уведомления отражаются счётчиком.
- Переход из уведомления должен вести к соответствующей заявке, поездке или сообщению, если такая связь предусмотрена API.

## 9. Технические состояния

- Загрузка: нейтральный экран с зелёным индикатором, без ложного сообщения об ошибке.
- Нет интернета: отдельный экран с объяснением и кнопкой «Обновить».
- Общая ошибка: отдельный экран «Не удалось выполнить действие» и кнопка повтора.
- Заблокированный аккаунт: отдельный экран с причиной и недоступностью запрещённых действий.
- Повторный запрос после восстановления сети должен обновлять текущий экран, а не создавать дублирующий маршрут в навигации.

## 10. Контракт API, важный для тестирования пассажирской части

Все пути ниже имеют префикс `/api/v1`.

| Сценарий | Метод и путь | Ожидание |
|---|---|---|
| Профиль | `GET /me` | Имя, фамилия, аватар, рейтинг, поездки, телефон, город, срок блокировки |
| Редактирование профиля | `PATCH /me` | Обновлённые разрешённые поля |
| Аватар | `PUT /me/avatar` | Multipart-поле `file`, JPEG/PNG/WebP до 5 МБ |
| Мои бронирования | `GET /bookings/mine?status=active\|completed\|cancelled` | Список по выбранному состоянию |
| Детали брони | `GET /bookings/{id}` | Полные данные поездки и брони |
| Условия отмены | `GET /bookings/{id}/cancel-preview` | Предупреждение, возврат, санкции/счётчик |
| Отмена | `POST /bookings/{id}/cancel` | Отменённый статус либо блокировка по правилам |
| Тестовая оплата | `POST /bookings/{id}/pay` | Немедленный статус «Оплачено» |
| Жалобы | `GET /me/complaints` | Список жалоб пользователя |
| Непрочитанные | `GET /notifications/unread-count` | Объект `{unread}` |

## 11. Приёмочный чек-лист

### A. Первый запуск и аккаунт

- [ ] A01. Новый пользователь видит онбординг в правильной последовательности.
- [ ] A02. Завершение онбординга открывает выбор города/начало работы.
- [ ] A03. Поиск города фильтрует список; выбор сохраняется.
- [ ] A04. Валидный телефон переводит к SMS-коду.
- [ ] A05. Код `111111` принимается; другой полный код показывает русскоязычную ошибку.
- [ ] A06. Регистрация требует имя и позволяет выбрать/снять аватар.
- [ ] A07. Пользователь выбирает роль и может переключить её позднее.
- [ ] A08. Выход очищает сессию и возвращает на вход.

### B. Поиск и просмотр поездок

- [ ] B01. Список поездок загружается и корректно показывает пустое состояние.
- [ ] B02. Более релевантные по рейтингу/времени карточки расположены выше.
- [ ] B03. Две одинаковые поездки видны одновременно, но статус «Идёт регистрация» имеет только активная.
- [ ] B04. Переключение «Автомобили/Автобусы» меняет набор карточек.
- [ ] B05. Детали содержат маршрут, остановки, места, услуги, цены, авто и водителя.
- [ ] B06. UTC-время показано в локальном часовом поясе.
- [ ] B07. Относительные фото `/media/...` загружаются с базового адреса API.
- [ ] B08. При отсутствии отзывов выводится «5 звёзд, нет отзывов» и `5,0`.

### C. Геолокация и фильтры

- [ ] C01. При первом использовании корректно запрашивается системное разрешение.
- [ ] C02. Разрешение геолокации применяет координаты/радиус.
- [ ] C03. Отказ не блокирует сценарий: доступен поиск по названию города.

## 13. Известные неоднозначности — не считать разрешением что-либо выдумать

- В одном общем тексте лимиты дублирования поездок были обозначены переменными `N` и `X`; отдельный стикер задаёт конкретное правило: одна прямая и одна обратная поездка в сутки, публикация не более чем на 3 дня вперёд. Для тестирования применяется конкретное правило со стикера.
- Точная формула рейтинга не задана; проверяется только направление влияния завершённых поездок и отмен.
- Точные габариты и вес посылок S/M/L должны приходить из согласованного дизайна/API. Если значений нет, это вопрос к владельцу продукта, а не основание придумывать числа.
- Поиск по центру города при отсутствии координат остановки является известным ограничением данных.
- Если макет показывает реальный SMS или банковскую форму, тестовые правила `111111` и мгновенная заглушка оплаты имеют приоритет.
