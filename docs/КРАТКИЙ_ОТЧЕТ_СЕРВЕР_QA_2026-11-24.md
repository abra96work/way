## Подтверждённый баг

### QA-SRV-001 — Parcel-only запрос с `seats: 0` отклоняется

- **Приоритет:** P1
- **Severity:** Major
- **Тип:** backend contract / integration
- **Сценарий:** отправка посылки без пассажирского места.
- **Шаги:** создать parcel-only бронирование и передать `seats: 0`.
- **Факт:** API отвечает `422`, потому что входная схема требует `seats >= 1`.
- **Дополнительное наблюдение:** запрос с `seats: 1` принимается, но сервер затем сохраняет и возвращает `seats: 0`.
- **Ожидание:** контракт явно принимает `seats: 0` для `kind=parcel` либо поле мест не требуется для parcel-only; OpenAPI и фактическое поведение совпадают.
- **Риск:** корректный клиент, следующий OpenAPI/бизнес-правилу «посылка без места», получает ошибку валидации; клиенты вынуждены отправлять фиктивное значение.
- **Рекомендация:** сделать валидацию зависимой от типа бронирования и добавить интеграционный тест `parcel + seats=0`.

## Рекомендация по безопасности

### QA-SRV-REC-001 — Добавить HTTP security headers

- **Приоритет:** P3, не блокер.
- На HTTPS-ответах не обнаружены `Strict-Transport-Security`, `Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options` и `Referrer-Policy`.
- Прямого продуктового требования нет; рекомендуется настроить заголовки в Caddy.
