## 1. Executive summary

Backend и заметный объём Flutter UI хорошо покрыты автотестами: 156 backend-тестов и 124 Flutter-теста прошли, анализаторы чистые, debug/release APK собираются. Но сквозной продукт к приёмке не готов:

- release APK не содержит `android.permission.INTERNET`;
- вход принимает только белорусский `+375`, российский `+7` ввести нельзя;
- водитель не может открыть поездку, обработать заявку, подтвердить/отклонить пассажира, отменить поездку или пройти блокировку через UI;
- чат и пассажирская отправка посылки заменены заглушками;
- сессия, refresh token и пройденный онбординг не сохраняются;
- роль при регистрации игнорируется;
- обязательная проверка фотографии водителя по умолчанию отключена;
- контракт отмены не содержит суммы и срока возврата.

Подтверждено **16 дефектов**: **3 P0, 10 P1, 2 P2, 1 P3**. Severity: **1 Blocker, 4 Critical, 10 Major, 1 Minor**.

## 4. Подробные баг-репорты

### QA-001 — Release APK не имеет доступа в интернет

- Компонент/роль: Android release, обе роли. **P0 / Blocker / Integration**.
- Предусловия: собрать release APK.
- Шаги: открыть manifest готового APK через `apkanalyzer manifest permissions`.
- Факт: camera/location есть, `android.permission.INTERNET` отсутствует.
- Ожидание: release APK имеет INTERNET и обращается к API.
- Доказательство: `mobile/android/app/src/main/AndroidManifest.xml:1-8`; INTERNET есть только в `src/debug`/`src/profile`; анализ свежего APK подтвердил отсутствие.
- Воспроизводимость: 100 %. Влияние: не работают авторизация, поездки, изображения, оплата и чат.
- **Комментарий Claude (25.11):** Актуален, но уже исправлен в рабочей копии основной папки: `INTERNET` добавлен в `src/main/AndroidManifest.xml`, не закоммичено. Ещё две ловушки release APK: (1) без `--dart-define=API_BASE_URL=...` приложение ходит на `http://10.0.2.2:8000` (адрес эмулятора) — APK для сдачи собирать только с адресом сервера; (2) Android 9+ запрещает обычный `http://` в release — сервер должен быть на HTTPS (план: Caddy), иначе нужен `usesCleartextTraffic`.

## 7. Ограничения и риски

- Физический Android/emulator end-to-end не использовался; APK проверен сборкой и manifest-анализом.
- iOS не проверялся: среда Windows.
- Passenger/technical widget tests используют 375×812. Большинство driver tests используют искусственную высоту 900–1400; 375×812 для них не доказан.
- Двухустройственный realtime chat не запускался: клиентский чат отсутствует; backend chat tests прошли.
- Публичный сервер не проверялся; release APK всё равно заблокирован QA-001.
- Первый единый pytest не дал summary за разумное время; все файлы прошли отдельными модульными прогонами.
- Driver cancel переводит брони в cancelled, но не помечает Payment refunded аналогично passenger cancel. Основная спецификация формулирует возврат в G для пассажирской отмены, поэтому это высокий продуктовый риск/вопрос, не отдельный баг.
- Расширенный checklist требует 4 вкладки driver trips и 10 поездок/неделю. Основная спецификация имеет приоритет; текущие 2 объединённые вкладки отмечены как расширенный gap, не входят в 16 багов.
