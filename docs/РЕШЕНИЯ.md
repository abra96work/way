# Вопросы и решения по ходу разработки

Рабочий список для себя: что было неясно, что решили и почему.
Оформим к сдаче. Принцип, о котором договорились: **требования со стикеров в Figma
важнее макетов**; если на стикере ничего нет — берём из макета.

## Правила продукта

| Вопрос | Решение | Почему |
|---|---|---|
| Нужна ли админка | Не делаем | Заказчик подтвердил, что не нужна (23.11) |
| На сколько дней вперёд публиковать поездку | Не дальше **3 дней** | Стикер с требованиями. Сначала сделали 7 дней под календарь в макете, вернули к стикеру |
| Сколько поездок в сутки | 1 поездка + 1 обратная в одни местные сутки | Стикер |
| Лимит в неделю | **10** за календарную неделю (пн–вс) | На стикере «X в неделю» без числа, число из макета «На неделе 3 / 10». Настройка `PUT_TRIP_WEEK_LIMIT` |
| «Сутки» по какому времени | Местное время Екатеринбурга (Asia/Yekaterinburg) | Целевой регион; на сервере всё хранится в UTC |
| Комиссия | 10 % **сверху** цены водителя, округление до рубля | Цифры в макетах (600 − 50 = 550) — заглушки; водитель получает свою цену |
| Код из СМС | Всегда `111111` | ТЗ |
| Оплата | Заглушка: «Оплатить» → сразу «Оплачено» | ТЗ |
| Отзывы | Полностью в базе и API, но без экранов; везде «5 звёзд, нет отзывов» | ТЗ. API за флагом `PUT_REVIEWS_ENABLED` |
| Санкции за отмены | 2 отмены «после регистрации» за 30 дней → блокировка на 30 дней | ТЗ |
| Возврат при отмене | Возвращается оплаченная в приложении комиссия; срок — 10 дней (`PUT_REFUND_PERIOD_DAYS`); сумма и срок в cancel-preview и в ответе отмены. При отмене поездки водителем — возврат всем оплатившим | Требование 5.7; оплата — заглушка, срок условный (QA-011, QA-017, 25.11) |
| Фото лица водителя «проверяет администратор» | Загрузка есть, проверка выключена (`PUT_REQUIRE_DRIVER_FACE_APPROVAL=false`) | Админки нет по решению заказчика — одобрить некому; включается флагом (QA-010) |

## Поездка: создание и публикация

| Вопрос | Решение | Почему |
|---|---|---|
| Город в свободном адресе | Город берётся из текста после запятой + подсказки городов | Бэкенду нужен `city_id`, а в макете адрес вводится текстом |
| Время прибытия | Добавили необязательное `arrival_at`; раньше отправления — значит на следующий день | Есть в макете, не было в API |
| Цены доп. услуг и посылок | Фиксированные: услуга 150 ₽; посылки S/M/L — 150/250/350 ₽ | В макете нет поля для ввода цены |
| Размер большой посылки | до 80×60×50 см и 30 кг | Как в макете |
| «Без проезда пассажира» у посылок | Всегда включено, не переключается | В бэкенде посылка всегда едет без пассажира |
| «Сохранить шаблон» | Сохраняет поездку черновиком, он в «Мои заказы» с меткой «Шаблон» | Отдельной сущности «шаблон» в ТЗ нет |
| Шторка «Опубликовать поездку?» | Используется и при создании, и для обратной поездки | Один и тот же смысл |
| Маршрут обратной поездки | Только для чтения (без ×) | Сервер зеркалит исходную поездку целиком |
| Номер заказа «Заказ №…» | Сквозной номер с 1001 | В базе только UUID, в макете номер |

## Поездка: после публикации

| Вопрос | Решение | Почему |
|---|---|---|
| Можно ли редактировать поездку с пассажирами | **Нет** — только количество мест и «Завершить приём пассажиров»; «Редактировать» показывает «Редактирование недоступно» | Текст в макете: «изменить можно, пока не присоединится первый пассажир». Иначе нужны правила для оплаченных броней |
| Количество мест | Не меньше уже занятых и не больше, чем мест в машине | Нельзя «выселить» пассажиров |
| Удаление поездки | Только без единой брони (даже отклонённой/отменённой), иначе — «Отменить». Редактирование после отклонённой заявки разрешено | Удаление стирало бы брони, оплаты и чат; отклонённый пассажир «не присоединился» (QA-012, 25.11) |
| «Мест для пассажиров 10 из 24» | Занято из всего | По двум макетам: после уменьшения «10 из 20» |
| «Завершить приём пассажиров» | Новое в API: поездка пропадает из поиска, новые брони запрещены, записанные остаются; можно возобновить | Было в макете, не было в бэкенде |
| Телефон пассажира | Водитель видит **после принятия заявки** (и сразу при быстром бронировании); никому больше | Макет профиля пассажира «до / после принятия» |
| Где принимается решение по заявке | На экране «Отклик» («Отклонить / Подтвердить бронь»); профиль пассажира только показывает | Макет «Отклик» |

## Редактирование поездки

| Вопрос | Решение | Почему |
|---|---|---|
| Сколько шагов | Открывается с маршрута, дальше автомобиль и доп. услуги; цены — кнопкой «Изменить стоимость» | Стрелка в макете ведёт на «Шаг 2 из 4» |
| Счётчик «Шаг N из 4» | **Убран** до выяснения | Шага 1 в редактировании не видно; не путать проверяющих |
| Тип транспорта | При редактировании не меняется | Шаг 1 не показывается |

**Открыто:** сколько шагов у редактирования и можно ли менять тип транспорта — уточнить у заказчика.

## Водитель: профиль и машины

| Вопрос | Решение | Почему |
|---|---|---|
| Галочка «проверено» у машины | Не показываем | СТС никто не проверяет — не обещаем проверку |
| Фото СТС | Хранится (`PUT /cars/{id}/sts`), никому не отдаётся, только признак `has_sts` | Есть в макете; проверки в этой версии нет |
| Камера с рамкой для СТС | Системная камера / файлы | Своя камера — отдельная большая работа |
| Госномер | Добавили необязательное поле в форму ТС | В макете поля нет, а номер показывается в списке и в поездке |
| Выход из аккаунта | С подтверждением; отзываем refresh-токен | Безопасность |

## Технические договорённости

- Время на сервере хранится в UTC (SQLite теряет часовой пояс).
- Чат по WebSocket, хаб соединений в памяти процесса → API работает **одним воркером**.
- Деньги — целые рубли.
- Ошибки API в формате `{code, message, details}`, `message` на русском — его и показываем пользователю.
- Водительская часть — `features/driver`, пассажирская (GPT) — `features/trips`; общие файлы `app.dart` и `pubspec.yaml`.
